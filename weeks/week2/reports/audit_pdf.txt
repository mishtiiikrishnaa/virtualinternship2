Executive summary
The report presents a ten-module Python curriculum across thirty teaching hours, with ninety-minute sessions,
three interactive activities per module, and appendices A to G. It includes an evidence map (Section 2), a session
plan (Section 4), lesson plans for modules 1 to 10, assessment strategy (Section 15), and validation (Section 18).
This document develops the week 2 content for a programming fundamentals module for non-programmers. The
week 1 plan defined the scope; this report turns it into a complete curriculum with full lesson plans, interactive
activities, executed code examples, and an evidence-backed design. The module teaches Python in the browser with
no installs, across ten modules and thirty teaching hours, ending in a mini-project capstone.
Every technical concept is explained in plain English first, then tied to a real-life analogy that states where it breaks
down. Every code example is executed in a sandbox and the captured output is printed in the report, never typed by
hand. Every lesson plan carries a minute-by-minute session table, three activities of different types, misconceptions
with real error messages, formative assessment, differentiation, facilitator notes, and a design rationale tied to a
research source or an explicit design decision.
The final deliverable is a Word document that presents the complete curriculum, with lesson plans, topics, learning
activities, annotations, examples, and an interactive activity set. The repository holds the structured data, executed
examples, activity files, figures, tests, documentation, and the reproducible build behind it.

1 About this curriculum
This internship offer was received on 2 November 2026 and the internship runs from 2 November 2026 to 30
November 2026. This week 2 report was prepared on 6 November 2026. It develops the content and curriculum
building task: the aim is to introduce the fundamentals of programming to non-programmers with practical
examples that are easy to grasp.
The learners are adults or students who have never written a line of code. Their prior knowledge is everyday
computer use only. The curriculum assumes no programming background, no installs, and a browser. It does not
assume any maths beyond counting.
By the end of the module, a learner will be able to: describe a task as steps, store information in variables, ask and
show through input and output, choose with conditionals, repeat with loops, bundle steps into functions, organise
values into lists and dictionaries, read and write files, read a traceback, and combine the taught concepts into one
working small program they can explain in plain words.

5 Module 1: Computational Thinking And Problem Decomposition
Module m1 of 10 - computational thinking and problem decomposition. Duration 180 minutes. Prerequisites: none.
Objectives: m1-o1, m1-o2 (describe a small task as a sequence of steps in plain words; explain why the order of
steps matters in a program).

plain english and the real-life analogy
Before any code, learners describe a task as a clear list of steps in plain words.
Real-life analogy: giving directions to a friend who has never seen the street: write the steps in order, one after
another, no skipping.
Where this analogy breaks down: the friend might read faster than you meant; in code the computer cannot
improvise.

worked example: a complete runnable program
No Python is run here. Pseudocode only: 1 open the diary, 2 turn to page 3, 3 read the entry, 4 close the diary.
Line-by-line annotation: line 1: we call the list of steps a variable called steps. Line 4: each line is one instruction, in
order, like a recipe.

plain english and the real-life analogy
A variable is a name for a value the program can read and change, like a labelled box.
Real-life analogy: a labelled box where you can put a number or a word, and later take the label off and use a

Where this analogy breaks down: the box is not a box; reassigning changes what the name points to, not the box.

name = "meghana"
age = 26

print(age)
print(height_cm)

Appendix D: glossary
Term                                                               Plain definition
algorithm                                                          a step-by-step set of instructions that solves a task

boolean                                                            a true or false value, like yes or no

breakpoint                                                         a pause point in code where the program stops so you can look at
                                                                   the values

capstone                                                           the final mini-project where learners combine ideas into one
                                                                   finished program

collection                                                         a group of values stored together, such as a list or a dictionary

conditional                                                        a choice in a program that runs different steps depending on the
                                                                   situation

debugging                                                          finding and fixing mistakes in a program

dictionary                                                         a collection that pairs each name with a value, like a contacts list

error message                                                      the computer note that explains what it did not understand or what
                                                                   went wrong

float                                                              a number with a decimal point, like 3.5

function                                                           a named, reusable set of steps that does one job

integer                                                            a whole number, like 5, without a decimal point

input                                                              how information travels into a program from the user

iteration                                                          one pass through a loop, where the loop variable takes the next
                                                                   value

list                                                               an ordered collection of items, like a shopping list

loop                                                               a structure that repeats steps until a condition changes

module                                                             one teaching unit, about three hours, that builds on the previous
                                                                   one

Parsons problem                                                    a task where learners order scrambled lines of code instead of
                                                                   writing from scratch

program                                                            the set of instructions a computer follows, written by a programmer

Python                                                             the teaching language; it reads clearly and runs in a browser

return                                                             the value a function sends back to whoever called it

sequence                                                           the order in which steps happen, one after another

string                                                             text, like a name or a sentence, written in quotes

syntax error                                                       a mistake in the shape of a code sentence, so the computer cannot
                                                                   parse it

variable                                                           a named place that holds a value that can change, like a label on a
                                                                   shelf
